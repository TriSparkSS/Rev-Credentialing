1. Introduction

1.1 What Is Revantage CRM?

Revantage CRM is a healthcare credentialing management system. It helps a credentialing team track when doctors (providers) and medical groups (practices) get approved to work with insurance companies (payers).

The system replaces spreadsheets and email chains with one central place to:

  • Store provider and practice information
  • Track each credentialing application from start to finish
  • Collect and store required documents
  • Assign tasks and send reminders
  • Report on delays, productivity, and compliance

1.2 Business Goal

When a provider joins a practice or a practice wants to bill a new payer, a credentialing application must be submitted. This process can take weeks or months. Revantage CRM makes that process visible, measurable, and auditable.

1.3 What This Document Covers

This guide walks through every module of the system in simple, step-by-step language. Developers, testers, project managers, and clients can all use this document to understand how the product works.

4. Getting Started (Installation)

4.1 Requirements

  • PHP 8.3 or higher
  • Composer
  • Node.js and npm
  • SQLite or MySQL database

4.2 Step-by-Step Setup

Step 1 — Install PHP dependencies:

composer install

Step 2 — Environment file:

cp .env.example .env
php artisan key:generate

Step 3 — Database migration:

php artisan migrate

Step 4 — Seed default data:

php artisan db:seed

Step 5 — Optional email templates and SLA rules:

php artisan db:seed --class=Phase2Seeder

Step 6 — File storage link:

php artisan storage:link

Step 7 — Frontend assets:

npm install
npm run build

Step 8 — Run the application:

php artisan serve

5. Login and Access

5.1 Admin Login

  3. You are redirected to /admin/dashboard

  1. Open /portal/login

6. System Architecture

6.1 Three Portals, One Database

┌─────────────────┐ │ Admin Portal │ │ (Full Control) │ └────────┬────────┘ │ ┌──────────────┼──────────────┐ ▼ ▼ ▼ ┌──────────┐ ┌──────────┐ ┌──────────┐ │ Provider │ │ Practice │ │ REST API │ │ Portal │ │ Portal │ │ (Sanctum)│ └──────────┘ └──────────┘ └──────────┘ │ │ │ └──────────────┴──────────────┘ │ ┌────────▼────────┐ │ Database │ └─────────────────┘

6.2 Key Relationships

  • A User links to one Provider OR one Practice
  • A Provider can belong to many Practices
  • A Credentialing Case links Provider + Practice + Payer + Status
  • Each case has a checklist, tasks, emails, and SLA timers

7.6 Credentialing Cases (/admin/credentials)

Create a case — step by step:

  1. Go to Credentials → Create
  2. Select Provider, Practice, Payer, Location
  3. Choose Case Type, Priority, Assigned Admin
  4. Save — case number and checklist are auto-created
  5. SLA timers start based on status category

Download Packet: ZIP of all case documents from case detail page.

10. Credentialing Case Workflow

10.1 Typical Lifecycle

Intake → Document Collection → Internal Review → Submitted to Payer → Payer Review → Approved (or Denied)

10.2 Common Statuses

StatusMeaning
Not StartedCase created, work not begun
In ProgressActive work by Revantage team
Waiting on ProviderProvider must submit documents
Waiting on PracticePractice must submit documents
Submitted to PayerSent to insurance company
Payer ReviewPayer is processing
ApprovedCredentialing complete

10.3 On Status Change

  1. Status history saved
  2. Activity log updated
  3. Delay owner may auto-update
  4. SLA timers synced

11. Documents and Checklists

  1. Case created → checklist seeded from payer requirements
  2. Document uploaded → matching checklist item marked received
  3. Version history kept for all re-uploads
  4. Expiry dates tracked — dashboard alerts at 30 days
  5. Credentialing packet ZIP available from admin

12. Tasks and Kanban Board

Tasks link to cases and assigned admins. Kanban columns: Overdue, Due Today, Upcoming, Completed. SLA engine can auto-create payer follow-up tasks.

13. Email Center and Templates

Send templated outbound emails with merge fields (e.g. {{case_number}}). Log inbound emails and import attachments as documents. Templates managed at /admin/master/email-templates.

22. Testing Guide

22.1 Admin Test Flow

  1. Login as admin → Create payer with document requirements
  2. Create provider and practice → Link them
  3. Create credentialing case → Upload document
  4. Verify checklist updates → Change status → Export report

  1. Login as provider → Upload document → Verify in admin
  2. Login as practice → View linked providers → Upload document
php artisan test

23. Deployment Checklist

  • Set APP_ENV=production and APP_DEBUG=false
  • Configure MySQL and mail settings in .env
  • Run migrate, seed, storage:link, npm run build
  • Set up cron for schedule:run
  • Change default admin password
  • Enable HTTPS
